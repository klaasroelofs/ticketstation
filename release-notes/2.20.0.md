## What's new in 2.20.0

### Copy an event
- **Copy an event with everything in it.** Select an event in the Events list and click *Copy* in the actions menu. The copy gets all tickets of the event (child tickets under their copied parent) with prices, VAT, ticket designs and background images, plus the seat charts: every seat comes over free, also seats that were sold in the original. Orders and the waiting list are not copied.
- **Nothing goes on sale by accident.** The copy and its tickets are unpublished, and automatic publishing is switched off, because the old publish dates have passed. Adjust the dates, switch automatic publishing on again if you use it, and publish when you are ready.

### Coupons per event
- **Limit a coupon to whole events.** A coupon now has a *Valid for events* field next to *Valid for* (tickets). All tickets of those events count, also tickets you add to the event later. Both fields can be combined; leave both empty for the whole order.

### Waiting list
- **Set the waiting list per event.** Every event has a *Waiting list* setting: follow the Configuration (the default), on, or off for this event. So you can use a waiting list for one sold-out show without switching it on everywhere, or switch it off for a single event.
- **Its own mail for the payment link.** The payment link that goes to a waiting-list customer when tickets come free now has its own template, *Waiting list payment link*, on the Templates screen. You can use `{eventname}` for the event the customer was waiting for and `{removal_days}` for the number of days the link stays valid, after which the unpaid tickets are released again.

## Check before you update
- **The new waiting-list mail starts as a copy of the payment-link mail.** Until you edit it, waiting-list customers get the same text as before. Add `{eventname}` and `{removal_days}` in the *Waiting list payment link* template to tell them which event it is and how long they have to pay.
